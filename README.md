# タスク管理アプリ

ビルド不要・サーバー不要のシンプルなカンバン式タスク管理アプリです。`index.html` をブラウザで開くだけで使えます。

## 使い方

1. `index.html` をブラウザで開く（ダブルクリックでOK）
2. 「+ タスク追加」からタイトル・詳細・ステータス・期限・優先度・カテゴリ・チェックリストを入力
3. カードをドラッグ&ドロップして列間を移動、列内でも自由に並び替え可能。タッチ端末などドラッグが使いづらい場合は、カードを開いて「ステータス」欄から列を選び直すこともできる
4. カードをクリックすると編集・削除ができる
5. 列見出しをクリックすると列名を変更、見出しの✓ボタンでその列を「完了扱い」に切り替え（完了扱いの列に入ったタスクは期限超過表示をしない）、末尾の「+ 列を追加」で新しい列を作成（追加時に完了扱いにするかも指定可）
6. ヘッダーの検索欄でタイトル・詳細をキーワード検索、セレクトでカテゴリ・優先度による絞り込みが可能
7. 「並び替え」セレクトで表示順を手動/期限順/優先度順に切り替え（期限順・優先度順を選んでいる間は列内のドラッグ並び替えは無効、列間の移動は可能）
8. テーマボタンで自動（OS追従）/ライト/ダークを手動切り替え
9. 通知ボタンでブラウザ通知を許可すると、期限当日・期限超過のタスクがある日に1回通知が届く
10. ヘッダー左上のボード切り替えセレクトと+/✎/×ボタンで、ボード（カンバン一式）を複数作成・名称変更・削除できる。ボードごとに列とタスクは独立している
11. 「エクスポート」で現在のボードのタスク・列一式をJSONファイルにダウンロード、「インポート」で読み込んで現在のボードへ復元・移行

## 機能

- カンバンボード（列はカスタマイズ可能）とドラッグ&ドロップ、列内の手動並び替え
- タスク編集モーダルの「ステータス」欄からもドラッグなしで列移動が可能（タッチ端末での操作を補助）
- タスクのCRUD（追加・編集・削除）とサブタスク/チェックリスト
- 期限・優先度（高・中・低）の管理、期限超過の強調表示（列ごとに「完了扱い」を設定でき、完了扱いの列では期限超過表示をしない）、期限が2日以内に迫ったタスクは「まもなく」バッジで表示
- タイトル・詳細のキーワード検索、カテゴリ/タグ分け・フィルタリング
- 表示順を手動/期限順/優先度順から選択できる並び替え機能
- テーマの手動切り替え（自動/ライト/ダーク）。「自動」時はOSのライト/ダークテーマに追従
- 期限当日・期限超過のタスクをブラウザ通知で知らせるリマインダー（通知ボタンで有効化、1日1回）
- ボードを複数作成し、用途ごとに列・タスクを分けて管理（既存データは初回起動時に自動で1つ目のボードへ移行）
- JSONによるエクスポート/インポート（ボード単位でのバックアップ・別ブラウザへの移行）
- ブラウザの `localStorage` へ自動保存（ブラウザを閉じても消えない）
- スマホ幅にも対応（列の削除・完了扱いボタンはタッチ端末でも常時表示）

## 技術構成

素のHTML / CSS / JavaScriptのみで、フレームワークやビルドツールは使用していません。

| ファイル | 役割 |
|---|---|
| `index.html` | 画面構造 |
| `style.css` | スタイル |
| `app.js` | タスクの状態管理・描画・localStorageへの永続化 |
| `requirements.html` | 要件定義書 |
| `mockup.html` | UIモックアップ（style.cssを読み込んだ静的な画面サンプル、操作不可） |
| `architecture.html` | 画面遷移図・データモデルER図・APIシーケンス図 |

## データ保存について

タスク・列はボードごとに同一ブラウザの `localStorage`（キー: `task-manager-app:tasks:<ボードID>` と `task-manager-app:columns:<ボードID>`）に保存され、ボード一覧は `task-manager-app:boards` に保存されます。別のブラウザや別の場所にコピーした `index.html` からは、保存済みのデータを参照できません。別環境へ持ち出す場合は「エクスポート」でJSONを書き出し、移行先で「インポート」してください（インポートは現在のボードのデータを全置換します）。

## バックエンド（試作）

`backend/` に、独立した試作用のSpring Boot REST API（Java 17 / Spring Boot 4.1.1 / H2）を用意しています。既存のフロントエンド（`index.html` / `app.js`、localStorage保存）とは接続しておらず、要件定義（サーバーサイド保存は対象外）を変更するものではありません。詳細は [`backend/README.md`](./backend/README.md) を参照してください。

## PostgreSQLコンテナ（Docker）

リポジトリ直下の `docker-compose.yml` で、`backend/` のSpring Boot APIが使用するPostgreSQLコンテナ（`taskmanager` データベース）を起動できます。

```
docker compose up -d   # 起動（localhost:5432、ユーザー/パスワード: taskmanager）
docker compose down    # 停止（データはボリュームに保持）
```

低メモリ環境向けに `postgres:16-alpine` を使用し、コンテナのメモリ上限を256MBに制限しています。バックエンドの起動方法は [`backend/README.md`](./backend/README.md) を参照してください。
